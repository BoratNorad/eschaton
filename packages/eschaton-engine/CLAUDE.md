# eschaton-engine: notes for Claude Code

This package is the rules layer for the ESCHATON game. Read README.md first.

## Integrating it into the game repo

1. Put this folder in the repo, for example at `packages/eschaton-engine`, and depend on it with a
   workspace or file path dependency: `"eschaton-engine": "file:packages/eschaton-engine"`.
2. Serve `data/eschaton_ledger.json` as a static asset, or import it on the server. In the
   client, load it with `loadLedger(url, sha)`, where `sha` is the contents of
   `data/eschaton_ledger.sha256`.
3. Run matches on the server (the Render web service) for multiplayer, and in the browser for
   single-player against an AI. Both use the same functions.
4. Do not edit `data/eschaton_ledger.json` by hand. It is generated by the dossier build kit;
   see "Updating the data" in README.md.

## Invariants to keep

- Every action returns a new state and never mutates its input. Keep it that way, because the
  server relies on it for undo, replay and broadcasting diffs.
- `npm test` must stay green. The parity test is the guard against the TypeScript formulas
  drifting from the Python build.
- Rule ids in `RuleError.rule` match the dossier's house rules (H-01 to H-13). Surface them in
  the UI so players can see why an action was refused.
- `tally()` is a placeholder (see README). Do not present its score as the canon C-05 index.

## Known data observation

With the field 50.54 m wide and REACH x 12.5 m, REACH 2 (25 m) already reaches every enemy
zone from both REACH-2 holders (PAK, ZAF), so H-04 never restricts a real launch with the
current data. This is a balance question for the dossier (the reach unit or the REACH
classes), not an engine bug.
